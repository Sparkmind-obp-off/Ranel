# Ranel — Strategic Roadmap & Gates

**Status:** LOCKED strategy; execution is conditional on evidence.

## 1. North-star sequence

```
FOUNDATION
  ↓
REAL DEMAND
  ↓
NARROW PAID OFFER
  ↓
REPEATABLE DELIVERY
  ↓
STANDARDIZATION
  ↓
SYSTEMIZATION
  ↓
AUTOMATION
  ↓
DISTRIBUTION SCALE
  ↓
MULTI-VERTICAL / COMPOUNDING
```

The existence of technical architecture does not authorize jumping ahead in this sequence.

## 2. Stage 0 — Foundation

Objective:
- public presence;
- clear brand;
- honest catalog;
- inquiry path;
- provider/account reality known;
- evidence method ready.

Current Ranel state:
**COMPLETED for the present Phase 2 public baseline.**

## 3. Stage 1 — Demand discovery

Objective:
- observe real operator problems;
- document recurrence;
- identify buyer;
- identify current workaround;
- identify willingness-to-pay signals;
- record counterevidence.

Gate:
A problem must be sufficiently evidenced before substantial product engineering.

## 4. Stage 2 — Paid offer test

Objective:
- select one narrow problem;
- define deliverable;
- define commercial boundary;
- test payment willingness.

Gate:
Real payment/deposit or another strong commercial signal becomes the decision input.

## 5. Stage 3 — Delivery proof

Objective:
- deliver manually;
- measure usage;
- measure time/support;
- measure objections;
- calculate delivery economics.

Gate:
The offer is deliverable and economically understandable.

## 6. Stage 4 — Standardize

Objective:
- document repeatable delivery;
- freeze a versioned baseline;
- define support and acceptance;
- identify repeated manual bottleneck.

Gate:
A repeatable workflow exists.

## 7. Stage 5 — Systemize

Objective:
- implement the smallest recurring workflow that is now justified;
- establish authenticated private workspace;
- create Core business truth;
- add only necessary persistence and provider adapters.

Gate:
Manual/no-code workflow has a demonstrated bottleneck and systemization has measurable value.

## 8. Stage 6 — Automate / AI

Objective:
- convert repeated low-risk actions into automation;
- introduce AI interpretation where structured data exists;
- establish recommendation and approval loop.

Gate:
Automation has clear inputs, outputs, policy, rollback/disablement, and measurable savings/value.

## 9. Stage 7 — Distribution scale

Objective:
- widen channels;
- standardize fulfillment;
- improve conversion and economics;
- add adjacent commerce where justified.

Gate:
Offer and delivery economics are stable enough to support additional demand.

## 10. Stage 8 — Second vertical

Objective:
- test transfer into another local-business vertical;
- preserve core model but validate vertical-specific workflow and economics.

Gate:
The first vertical provides enough evidence that the operating model is reusable.

## 11. Stage 9 — Multi-vertical engine

Longer-term:
- reusable Core;
- Control Center;
- vertical modules;
- catalog;
- demand intelligence;
- AI recommendations;
- commerce/supply;
- shared operational infrastructure.

Multi-tenancy is a later gate, not a starting assumption.

## 12. Current decision rule

At every gate choose one of:
- **CONTINUE**
- **NARROW**
- **REVISE**
- **DEFER**
- **STOP**

The decision must be supported by evidence, not by sunk engineering effort.

## 13. Immediate next sequence

Given the current Phase 2 state:
1. collect real operator evidence;
2. identify one narrow paid pilot;
3. agree commercial/fulfillment boundaries;
4. deliver manually;
5. measure outcomes and economics;
6. only then authorize systemization.

The long-term architecture remains locked while implementation remains evidence-gated.
